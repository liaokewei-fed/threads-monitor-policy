繁體中文

目前原型：Threads Post Monitor 目前沒有持久化的 Threads 貼文資料庫、應用程式備份或正式託管環境，也尚未啟動正式監測。營運者目前可直接移除本機環境中的 Threads Token、LINE Token 與 LINE User ID，並在 Meta 帳號設定撤回應用程式授權。

正式部署後：可透過以下方式提出刪除申請：

  1. 寄信至 h630603@yahoo.com.tw。
  2. 主旨填寫「Threads Post Monitor 資料刪除申請」。
  3. 提供 Threads 使用者名稱及刪除申請的簡短說明；請勿寄送密碼、Access Token 或 LINE 憑證。
  4. 一般申請只需精確 Threads 使用者名稱及申請內容。對涉及非公開識別資料的請求，營運者將以適當方式確認申請權限；無法確認時，不會揭露或交付任何資料。
  5. 經確認有效且可處理的申請，營運者將於 30 日內刪除其控制範圍內與申請相關的資料，並以電子郵件確認。

正式監測只持久化保存必要的貼文 ID 與去重狀態；通知完成後不持久化保存貼文全文。停止監測後，相關狀態於 30 日內刪除。Access Token 與 LINE User ID 僅在服務啟用期間保存，並於停止服務或撤回授權後 7 日內從營運者可控制的環境刪除。

目前沒有應用程式備份可供刪除。若未來新增備份，必須先更新本說明及隱私政策，載明備份中的刪除或到期方式。正式部署前，必須確認程式及操作流程能遵守上述期限。

English

Current prototype: Threads Post Monitor currently has no persistent Threads post database, application backup, or hosted production environment, and live monitoring has not been activated. The operator can currently remove the Threads token, LINE token, and LINE User ID from the local environment and withdraw the application's authorization through the applicable Meta account settings.

After production deployment: a deletion request may be submitted as follows:

  1. Email h630603@yahoo.com.tw.
  2. Use the subject “Threads Post Monitor Data Deletion Request.”
  3. Provide the Threads username and a short description of the deletion request. Do not send a password, access token, or LINE credential.
  4. A general request requires only the exact Threads username and request details. For a request involving non-public identifiers, the operator will use an appropriate method to confirm the requester's authority. If authority cannot be confirmed, no data will be disclosed or delivered.
  5. For a valid and actionable request, the operator will delete request-related data under the operator's control within 30 days and confirm by email.

Production monitoring will persist only the post IDs and deduplication state necessary for deduplication. Full post text will not be persistently retained after notification is completed. Related state will be deleted within 30 days after monitoring stops. Access tokens and the LINE User ID will be retained only while the service is active and will be deleted from environments under the operator's control within 7 days after the service stops or authorization is withdrawn.

There are currently no application backups to delete. If backups are introduced in the future, these instructions and the privacy policy must first be updated to describe deletion from or expiry within those backups. Before production deployment, the implementation and operating procedure must be verified to comply with the periods stated above.
